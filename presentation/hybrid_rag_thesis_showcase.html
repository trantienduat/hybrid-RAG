Research and Development of a Code Retrieval System Based on Hybrid-RAG Architecture Combining Knowledge Graphs and Semantic Search

Finding the Right Code with Hybrid-RAG
Using a Python code map and meaning-based search to answer questions about one repository.

Tran Tien Duat · Master of Software Engineering · 2026

Cách hiểu: Slide mở đầu phải nói rõ bài toán và phạm vi claim. Luận văn hỏi: khi người dùng hỏi về code, làm sao tìm đúng phần code và giải thích được các phần liên quan? Text search giúp tìm đoạn có ý nghĩa gần với câu hỏi, nhưng không tự cho mình biết các function nối với nhau thế nào. Vì vậy hệ thống dùng thêm code map được tạo từ Python source. Đóng góp ở đây là ghép các thành phần thành một hệ thống có thể kiểm tra, không claim phát minh ra một thuật toán retrieval hoàn toàn mới.

The problem · 02 / 15

The problem: code questions need both meaning and structure.

Example questionCheckout.checkoutevidence across files
demo_checkout/checkout.py
class Checkout:
  def checkout(self, cart):
    self.log.start()
    self._validate(cart)
    total = self._total(cart)
    self.payment.charge(total)
    self.log.end()
    return total
demo_checkout/payment.py
class PaymentGateway:
  def charge(self, amount):
    self._authorize(amount)
    self._capture(amount)
    return "ok"
Question example

“When Checkout.checkout runs, what is the sequence, including logging and payment?”

Meaning: find related code such as payment.py.

Structure: show which functions call, define or import each other.

Scale: keep the answer focused when evidence spans many files, modules or a monorepo.

Trust: show where the evidence came from and when a link is uncertain.

The system must combine semantic search with code structure, keep the context bounded, and make the evidence traceable.

Scope: evaluated on one pinned Python repository. Larger repositories and monorepos are motivation, not measured evidence.

Cách hiểu: Slide này đặt problem trước khi nói solution. Khi codebase lớn hơn hoặc trải rộng như một monorepo, evidence bị rải qua nhiều file, module hoặc service. Một câu hỏi có thể vừa hỏi “đoạn code này có ý nghĩa gì?” vừa hỏi “các phần của nó nối với nhau ra sao?”. Vector search có thể tìm source liên quan như payment.py, nhưng không tự biểu diễn đầy đủ các quan hệ CALLS, DEFINES và IMPORTS. Vì vậy problem của thesis là lấy được evidence vừa có meaning vừa có structure, trong context budget, có thể trace về source và chạy trong local boundary. Checkout chỉ là ví dụ làm problem dễ nhìn; benchmark chính vẫn là một pinned Python repository. Monorepo và repository lớn hơn là motivation/future validation, không phải evidence đã đo.

Research questions · 03 / 15

Three questions cover quality, cost and confidence.

RQ1 · Answer quality: Do Faithfulness, Answer Relevancy and Answer Correctness change compared with vector-only retrieval?

RQ2 · Time and tokens: How do search time, answer time and token counts change?

RQ3 · Confidence: Does the difference stay above zero in the paired 95% range?

Scope: Python code indexing · one fixed LlamaIndex Core snapshot · local Ollama · Java rejected explicitly.

A higher average is not enough; the range tells us how strong the result is.
Cách hiểu: Ba RQ tương ứng với ba thứ hội đồng cần biết. RQ1 hỏi chất lượng câu trả lời có tốt hơn không: Faithfulness, Answer Relevancy và Answer Correctness. RQ2 hỏi cái giá phải trả: retrieval time, generation time và token footprint thay đổi thế nào. RQ3 hỏi evidence có đủ mạnh không: chênh lệch quan sát được có còn hợp lý khi tính paired 95% confidence range hay không. Mean cao hơn chưa đủ để claim improvement; phải nhìn cả khoảng tin cậy.

Safety checks · 08 / 15

Bad input stops early; safe updates protect the index.

1 · Input checkPython repository + local Ollama onlyUnsupported Java/provider → reject
2 · Same-source checkRepository, source hash, schema and embedding modelMismatch → stop
3 · Prepare firstParse and embed before changing the databaseFailure → keep old data
4 · Safe updateWrite new records before removing old onesLess empty-index time
5 · New cacheGive the new index a new cache nameOld answers stay separate
These checks protect both the demo and the main test. They do not create new evidence.

Concrete checks: Java input → reject · source mismatch → stop the test · parse/embed failure → keep the old records.

Cách hiểu: Reliability không chỉ là trả được answer; còn là biết lúc nào phải dừng. Hệ thống reject input không hỗ trợ như Java và remote provider. Nó kiểm tra repository, source digest, schema và embedding model có cùng một run hay không. Khi update index, parse và embed xong trước rồi mới thay đổi database; ghi data mới trước khi cleanup data cũ để giảm khoảng thời gian index rỗng. Đây chưa phải atomic live cutover. Cache generation mới cũng giúp answer của snapshot cũ không lẫn vào snapshot mới. Các check này bảo vệ demo và benchmark, nhưng không tự tạo thêm evidence về answer quality.

What this thesis adds · 14 / 15

This thesis combines known parts into a system we can check.

Search: fixed rules for link questions, two-list local search, folder summaries and size limits.

Code map: Python code links plus optional Markdown, YAML and Dockerfile text.

Exploration: one-repository code map and multi-repository 3D/2D portal.

Safety: source tracking, safe updates, new cache names, local-only use and clear language limits.

Core 07 → Combine the two lists · detail · 1 / 1
Core 07: two result lists become one answer context. Here: we show how RRF combines their positions.

RRF combines list positions, not answer quality.

RRF(d) = Σ wₘ / (60 + rankₘ(d))
CombSUM · raw score sum

Adds raw scores; graph and vector scores use different scales.

Borda count · rank vote

Gives more points to higher ranks; not benchmarked here.

Learned reranker

An extra model that reorders results; adds latency and calibration.

RRF · chosen

Core 09 → How we build the 95% range · detail · 3 / 3
Core 09: each question stays paired. Here: we show what we average and repeat.

We build the 95% range from 30 question differences.

For each question and mode, average the three answers.
Compute Hybrid minus vector for the same 30 questions.
Bootstrap: resample the 30 paired differences, with replacement, 10,000 times.
Use the middle 95% — the 2.5th and 97.5th percentiles — as the range.
30 questions → 3 repeats → 30 differences → 10,000 bootstrap resamples; seed 42 gives the same result each time.
Cách hiểu: Mỗi câu chạy 3 lần ở cả hai mode. Mình average các repeats của từng câu, tính Hybrid − vector-only để có 30 differences, rồi resample 30 differences đó 10.000 lần. Khoảng giữa 95% bootstrap results là confidence range. Ba lần trả lời của một câu chỉ là repeats, không phải ba câu hỏi độc lập. Seed 42 giúp chạy lại vẫn ra cùng cách tính.

Research and Development of a Code Retrieval System Based on Hybrid-RAG Architecture Combining Knowledge Graphs and Semantic Search

Finding the Right Code with Hybrid-RAG
Using a Python code map and meaning-based search to answer questions about one repository.

Tran Tien Duat · Master of Software Engineering · 2026

Bài toán của luận văn là tìm đúng code evidence và giải thích được quan hệ giữa các phần code khi người dùng đặt câu hỏi về một repository. Semantic search tìm các đoạn gần nghĩa với câu hỏi; knowledge graph bổ sung cấu trúc như function nào định nghĩa, gọi hoặc import function nào. Hybrid-RAG kết hợp hai loại evidence này trong một hệ thống chạy local và có thể truy ngược về source. Đóng góp chính là cách tích hợp và kiểm chứng hệ thống, không phải một thuật toán retrieval hoàn toàn mới.

The problem · 02 / 15

The problem: code questions need both meaning and structure.

demo_checkout/checkout.py
class Checkout:
  def checkout(self, cart):
    self.log.start()
    self._validate(cart)
    total = self._total(cart)
    self.payment.charge(total)
    self.log.end()
    return total
demo_checkout/payment.py
class PaymentGateway:
  def charge(self, amount):
    self._authorize(amount)
    self._capture(amount)
    return "ok"
Question example

“When Checkout.checkout runs, what is the sequence, including logging and payment?”

Meaning: find related code such as payment.py.

Structure: show which functions call, define or import each other.

Scale: keep the answer focused when evidence spans many files, modules or a monorepo.

Trust: show where the evidence came from and when a link is uncertain.

Scope: evaluated on one pinned Python repository. Larger repositories and monorepos are motivation, not measured evidence.

Trong codebase lớn, evidence cho một câu trả lời thường nằm rải qua nhiều file và module. Câu hỏi về Checkout.checkout cần cả meaning — tìm được source liên quan như payment.py — và structure — biết các quan hệ CALLS, DEFINES và IMPORTS. Hệ thống còn phải giữ context trong token budget, truy ngược evidence về source và chạy trong local boundary. Fixture Checkout chỉ minh họa vấn đề; benchmark được đo trên một Python repository đã pin. Repository lớn hơn và monorepo là động lực mở rộng, chưa phải evidence đã đo.

Research questions · 03 / 15

Three questions cover quality, cost and confidence.

RQ1 · Answer quality: Do Faithfulness, Answer Relevancy and Answer Correctness change compared with vector-only retrieval?

Paired experimental design · 09 / 15

The statistical unit is the question—not each saved answer.

Confirmatory workloadllama-index-core30 questions

1. Fixed workload. Thirty questions cover three difficulty levels on one fixed LlamaIndex Core snapshot.

Answer model: gemma4:12b · Judge model: qwen2.5-coder:7b · Embedding model: nomic-embed-text.

Workload có 30 câu cố định: 10 simple, 10 medium và 10 hard. Mỗi câu chạy ba lần ở Vector-only và ba lần ở Hybrid, tạo 180 records để audit nhưng chỉ có 30 independent question units. Với từng metric, ba repeats được average trong mỗi question và mode; sau đó tính Hybrid − Vector cho đúng cùng một câu, tạo 30 paired deltas. Bootstrap resample 30 deltas này 10.000 lần với replacement và seed 42 để lấy paired 95% confidence interval. Pairing được giữ vì hai modes luôn được so trên cùng question.

Core 07 → Why RRF · detail · 1 / 1

Why use RRF instead of score fusion or a reranker?

RRF(d) = Σ wₘ / (60 + rankₘ(d))
CombSUM · raw score sum

Adds raw scores; graph and vector scores use different scales.

Borda count · rank vote

Gives more points to higher ranks; not benchmarked here.

Learned reranker

An extra model that reorders results; adds latency and calibration.

RRF · chosen

Combines rank positions; deterministic and lightweight. Not proven best.

Boundary: k = 60 follows the original RRF default; it was not tuned here. These alternatives were not experimentally compared.

CombSUM cộng raw scores nên cần calibrate thang điểm giữa graph và vector. Borda count cũng dựa trên rank nhưng chưa được benchmark trong luận văn. Learned reranker có thể mạnh hơn nhưng thêm model inference, latency và nhu cầu training hoặc calibration. RRF chỉ dùng rank position, deterministic và nhẹ, nên phù hợp với hai retrievers có score scale khác nhau. Đây là design choice, không phải bằng chứng RRF tốt nhất. k=60 theo default trong RRF paper và chưa được tune trên development set riêng.

Core 09 → How we build the 95% range · detail · 3 / 3

Bootstrap keeps the Vector–Hybrid pairing intact.

One metric at a timeHybrid − Vectormetric means

1. Average metric scores. For each question and mode, average the metric values from three repeats.

Với từng metric, ba scores của mỗi question và mode được average; phần text của ba answers không bị nối hay average. Cùng một question tạo một cặp và cho một delta Hybrid mean − Vector mean, nên 30 questions tạo 30 deltas. Mỗi bootstrap sample rút lại 30 deltas có replacement; một question có thể xuất hiện nhiều lần và question khác có thể không xuất hiện trong sample đó. Sau 10.000 samples với seed 42, percentile 2.5 và 97.5 của sample mean deltas tạo paired 95% CI. Resample delta giữ đúng pairing, không trộn Vector của câu này với Hybrid của câu khác.

Core 08 → What happens when something goes wrong · detail · 2 / 2

Each failure point leaves a visible system state.

Failure pointIndex stateSystem response
Validation failsNeither store changedReject unsupported language, path or remote Ollama URL
Parse, resolve or embed failsPublished run A remainsFail the task before database mutation
Publish, cleanup or metadata failsPartial or mixed records may remainFail the task; no cross-store rollback—retry or rebuild
Cache generation bump failsNew index remains usableDisable/fail open the cache; run uncached queries

Next: Core 09 separately checks source and index identity before accepting any benchmark measurement.

Validation fail thì stores chưa thay đổi. Parse, resolution hoặc embedding fail thì run cũ vẫn còn nguyên vì publish chưa bắt đầu. Nếu fail sau khi publish bắt đầu, FalkorDB và Qdrant có thể chứa partial hoặc mixed records vì không có transaction chung; task phải fail và operator cần retry hoặc rebuild, không được claim rollback tự động. Nếu Redis generation bump fail, index mới vẫn dùng được nhưng cache chuyển sang fail-open hoặc disabled. Evaluation preflight chặn benchmark khi source identity, schema, embedding model hoặc index run không khớp.

Core 15 → What remains to test · appendix · 1 / 1

Each open question has a next test.

Faithfulness + relevancy: ask independent human reviewers and use more independent questions.

Answer time + token use: measure the full request before claiming savings.

Other repositories: run larger, full-repository Transformers/LangChain tests.

Other comparisons: run BM25, graph-only and a documented external GraphRAG comparison.

Other languages: build and test a Java extractor before accepting Java repositories.

Hardware cost: measure VRAM, energy and concurrency before claiming efficiency gains.

Human review sẽ kiểm tra automated judge có phản ánh chất lượng thật hay không. Thêm independent questions giúp confidence interval ổn định hơn. Transformers và LangChain cần benchmark tương đương trước khi claim cross-repository robustness. BM25, graph-only và GraphRAG cần được chạy nếu muốn experimental comparison. Java extractor và resource hoặc energy measurements cần có trước khi mở rộng claim sang nhiều language và operational cost. Đây là các thí nghiệm tiếp theo, không phải evidence hiện tại.
